# 三维观点卡（3+3+4 法则）

技术介绍、科技新闻、财报分析，都不能写成百科词条或新闻播报。动笔之前先把三样东西想清楚，旁白篇幅大致按 3 : 3 : 4 分配。

## 三维

- 内行解说（约 30%）：客观底座。用业务语言讲清核心概念、关键组件、新闻细节或核心指标。只讲观众做判断需要的那几个，不求全。
- 顾问经验（约 30%）：一线的真实体感，做架构诊断、企业内训、在生产环境里跑系统、服务客户时看到的现象和踩过的坑。用第一人称说（“我们给企业做诊断的时候，常看到…”），并且要有场景：谁、在做什么、卡在哪。
- 核心认知（约 40%）：推翻一个外行共识，给出一个能被原样转述的顶层框架或金句（例如“甲是业务大脑，乙是推理大脑，丙是执行手脚”这种一句话结构）。开头、转折、结尾都为这句话服务。

## 怎么填卡

- insight.claim 是一句完整的话，观众能原样说给同事听。insight.against 写清它推翻的那个常见看法。
- insider 给 2–4 条，experience 给 1–3 条。每条是一个具体的点，不是一个话题名。
- 经验素材只来自需求里的“一线经验”和参考资料。没有素材时，写成不带数字、不点名客户的常见现象，source 标 draft，并在 toVerify 里提醒创作者换成自己的真实案例。不要编造“百分之九十的公司”这类数字。
- outline 给每一段标上它主要承担的那一维。核心认知要贯穿：开头预告，中段点破，结尾回扣。

## 写的时候

- 旁白里不出现“内行解说”“顾问经验”“核心认知”这些标签，它们只是策划用语。
- 经验段说“我们”，认知段敢下判断，解说段克制、准确。三种语气要听得出区别。

## 审稿时怎么查

- 删掉其中一维，这条视频会变成什么？只剩解说是百科，只剩经验是流水账，只剩认知是空喊口号。每一维都要有删不掉的句子。
- 经验段有没有具体场景？没有场景的“经验”是空话。
- 核心认知有没有在结尾被再说一次？
