# Video Scripter 短视频脚本创作工具

**一份需求，为每个发布平台各写一份拿来就能拍的脚本。**

Video Scripter 是一个短视频脚本工作台。把视频描述一次，勾选要发布的平台，每个平台都会得到一份单独的脚本：按该平台的受众、节奏和发布规则来写，还能根据分镜直接生成画面图片和视频片段。

它运行在你自己的电脑上，接入你已经在用的模型服务商，所有脚本、图片和视频都保存在你自己的文件夹里。

[English](README.md)

## 为什么用 Video Scripter

- **一份需求，五个平台。** 抖音脚本和 YouTube Shorts 脚本本来就是两种写法。每个平台各写一份，而不是一稿到处贴。
- **拿来就能拍。** 每个场景都有时间码，并写好旁白、屏幕文字、画面、镜头和声音。
- **拿来就能发。** 每份脚本都附带标题、封面文字、描述文案、话题标签和置顶评论。
- **旁白由智能体来写，而不是一条提示词写完。** 先在三维观点卡上想清楚要说什么，再用适合这份需求的技能来写，最后量化检查、审稿、修订，然后才围绕它生成脚本。
- **旁白你说了算。** 可以先让 AI 起草旁白，也可以粘贴自己的旁白，或在旁白编辑器里让任意一段重写。之后脚本会一字不差地围绕它生成。
- **自带分镜画面。** 任意场景都能按视频的画面比例（9:16、16:9、1:1、3:4 或 4:3）生成图片或视频片段，有 57 种画面风格可选。
- **模型随你选。** 内置十个服务商预设，从 OpenAI、Anthropic 到通义千问、豆包和本地 Ollama，也支持任何兼容 OpenAI 或 Anthropic 接口的服务。每份脚本都可以换模型。
- **内容归你所有。** 不用注册账号，不上云，不用安装依赖。所有内容保存在本地磁盘，并可打包成一个整齐的 `.zip`。

## 快速开始

需要 Node.js 20 或以上版本。

```bash
npm install
```

```bash
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='设置一个足够长的密码' npm start
```

打开 http://localhost:3789 ，点击 **开始创作**，用上面的邮箱和密码登录。`ADMIN_EMAIL` 和 `ADMIN_PASSWORD` 只在首次启动时用于创建管理员，之后可以省略；其他人在登录页自行注册。首次启动是演示模式，只返回占位文字，方便你在没有模型的情况下先熟悉流程。点击 **模型设置** 连接真实模型。

## 使用流程

### 1. 填写需求

只有主题是必填的，其余各项用来让结果更准。

| 字段 | 作用 |
| --- | --- |
| 主题 | 这条视频讲什么 |
| 发布平台 | 勾选几个平台，就写几份脚本 |
| 脚本结构、时长 | 叙事框架（或同时规定旁白口吻和语速的内容风格）和视频长度：自动（风格有自己适合的时长就用它，否则用平台常用时长）、平台常用的几档，或选 **自定义** 填 10 到 360 秒之间的任意时长 |
| 画面风格 | 选一种，或选两种混合；用于分镜描述和所有生成的图片、视频 |
| 核心信息、目标受众、语气风格 | 希望观众记住的那句话、写给谁看、听起来是什么感觉 |
| 品牌或创作者、行动号召 | 谁在说话，希望观众接下来做什么 |
| 一线经验 | 你亲眼见过的事：客户现场、踩过的坑、做出的结果。旁白会用你的口吻讲出来。不填的话，智能体只写不带数字、不点名客户的常见现象，并提醒你确认或替换 |
| 参考资料 | 事实、引语或一篇文章。模型被要求只使用这里或需求中出现过的数据和引语 |
| 旁白用于语音合成 | 把数字和符号写成读法，让语音合成读得正确 |
| 旁白 | **随脚本生成**：先写旁白，再围绕它生成脚本，中间不停。**先写旁白**：先起草旁白，由你修改。**用我的旁白**：打开编辑器，写或粘贴你自己的旁白 |
| 旁白智能体 | 默认开启：旁白分步骤策划、写作、审稿（见[旁白智能体](#旁白智能体)）。取消勾选则一次写完，更快 |
| 写作模型 | 用哪个网关和模型来写这份脚本 |

### 2. 编辑旁白（可选）

在需求下方选择 **先写旁白** 或 **用我的旁白**，就可以在生成其他内容之前，先把要说的话定下来。每个平台各有一个旁白编辑器：

- **一个阶段一段。** 起草出来的旁白，故事线的每个阶段对应一段。每一段都会显示它要完成什么、预计的时间码，以及当前字数和该阶段可容纳的字数。
- **时长进度条。** 按你要的时长显示当前字数（中文按汉字，英文按词）和预算，以及成片大约多长。旁白偏长也可以保留，成片会相应变长；**贴合时长** 可以把它调回去。
- **质检。** 边写边量化检查：字数是否超出预算、哪一口气太长说不完、有没有寒暄开场和结束预告词、平台会限流的词、选题点了名却没说出口的名字、太久没有转折的段落，以及三维配比。每条问题就显示在对应的段落下面。
- **三维观点卡。** 智能体动笔前定下的内容：人设、核心认知和它推翻的共识、内行解说的要点、一线经验、必须说出口的名字，以及录制前需要核实的事项。
- **润色。** 可针对某一段或全文：贴合时长、更口语、更有力、少术语、适配语音合成、按结构重排，或者直接写下你的修改要求。**智能体审稿** 会对当前的旁白（包括你自己写的）执行智能体的审稿步骤。每次改写都可以撤销。
- **用自己的文字。** 在空白编辑器里直接粘贴，或点 **粘贴旁白**。空行分段；没有空行时，每一行算一段。
- **段落。** 可以增加、删除和调整顺序。故事线始终显示在旁边作参考。

**生成脚本** 会围绕当前的旁白生成分镜、画面和发布素材，旁白原样使用。模型只允许加重读和停顿标记；如果它还是改了字，系统会把你的原文放回去，并在脚本上注明。在已生成的脚本上点 **编辑旁白**，可以打开它的旁白进行修改，再生成一份新脚本。还没生成脚本的旁白会保存在浏览器里，刷新页面不会丢。

### 3. 查看脚本

每个平台一个标签页，脚本边写边显示。一份脚本包括：

- **三个开场钩子备选**，从中挑一个开头
- **带时间码的分镜列表**，每个场景都有旁白、屏幕文字、画面、镜头和声音
- **只看旁白** 视图，方便录音或粘贴到语音合成工具
- **发布素材**：标题、封面文字、描述文案、转发导语、话题标签、置顶评论；三分钟以上的视频还有带时间戳的章节
- **三维观点卡**：旁白由智能体撰写时，附上它所依据的观点卡
- **板书蓝图**：风格是在讲一个结构时，用纯文本画出这条视频推演的那张板书或投屏图

**重新生成** 会重写这份脚本。**复制 Markdown** 和 **复制旁白** 可把内容复制到剪贴板。

### 4. 生成画面

当前使用的网关设置了图像或视频模型后，每个场景下会出现 **生成图片** 和 **生成视频** 按钮，把该场景的画面和镜头描述变成图片或视频片段，画幅取自需求里选择的 **画面比例**：9:16 竖屏（默认）、16:9 横屏、1:1 方形、3:4 竖版或 4:3 横版。图片和视频设置里的尺寸按竖屏填写，会自动按所选比例调换宽高；边长不会重新计算，所以 3:4 和 4:3 用的是模型最接近的尺寸。在需求里勾选 **同时为每个场景生成图片**，脚本写完后会自动为所有场景出图。

### 5. 导出

**下载 .zip** 会把脚本、旁白以及所有已生成的图片和视频打包成一个压缩包，按场景编号命名（见[你的内容](#你的内容)）。

## 旁白智能体

一条提示词写出来的旁白，读起来和别的旁白没有区别。智能体像一个写作团队那样分步骤来写，每一步都带着适用的技能：

1. **选用技能。** 依据平台、语言、风格、时长和需求里提到的内容。
2. **策划并写作。** 先填三维观点卡：谁在说话、观众该带走的那一个认知和它推翻的共识、内行解说的要点、一线经验、必须说出口的名字。然后照着这张卡写旁白，故事线的每个阶段一段。
3. **量化检查、审稿、修订。** 初稿先由代码来量，因为模型数不清自己写了多少字，也发现不了自己漏掉的名字。检查结果连同技能和观点卡交给审稿步骤：它先指出问题，再给出修订稿。量出来比初稿更差的修订不会被采用。

观点卡遵循解说类内容的 3 + 3 + 4 法则：约三成内行解说、三成一线经验、四成核心认知，技术选题不会写成百科词条或新闻播报。编辑器会显示实际量出的配比。

它对模型没有额外要求，只要能输入文字、输出文字，所以网关能连到的每个模型都可以用，演示模式下也能跑。策划和写作合并成一次模型调用，审稿是另一次请求：遇到每次调用要思考几分钟的模型，也不会让一个请求扛两次长调用。

### 技能

一个技能就是一份 Markdown 写的打法，放在 `skills/<名称>/SKILL.md`。文件头说明它在什么情况下适用、哪些步骤会读它。想教智能体新东西，加一个文件夹就行，不用改代码。

| 技能 | 适用于 | 内容 |
| --- | --- | --- |
| `spoken-delivery-zh` | 中文旁白 | 口播听觉留存律：一口气 14–20 个字、专名说出口、不寒暄开场、不预告结束 |
| `spoken-delivery-en` | 英文旁白 | 英文口播的同一套要求：短句、一句一事、几秒一个转折 |
| `retention-rhythm` | 中文旁白 | 完播节拍：前 3 秒、看完的理由、每 12–15 秒一次转折、长课的章节承接、无预警收尾 |
| `viewpoint-card` | 中文旁白 | 3 + 3 + 4 法则，以及观点卡怎么填、怎么查 |
| `wechat-channels-growth` | 视频号 | 完播率与熟人社交裂变双引擎、防限流违禁词、两种合规引流方式、发布素材 |
| `enterprise-ai-ontology` | 需求里提到 Palantir、Ontology、本体、智能体、企业 AI 等 | 新四层架构、Ontology 的微观构造（对象、关联、状态、事件、规则、动作、回写）和“三大脑”模型 |
| `consultant-whiteboard-lecture` | 顾问级白板授课风 | 一张图渐进推演、分章节、指向性口播、讲义转化 |
| `honest-sourcing` | 所有内容 | 事实、判断和经验分开；不编造数字、客户和引语 |

```
---
name: my-domain
title-zh: 我的行业知识
description: 用一句话说明它是做什么用的
lang: zh                     # 可选条件：lang、platforms、frameworks、groups、keywords、min-duration
keywords: Kubernetes, 容器
steps: plan, write, review   # plan、write、review（旁白的三步）和 script（画面与发布素材）
---
用 Markdown 写的打法。
```

## 脚本结构

十四种结构决定故事怎么展开，以及时长在各个阶段之间如何分配。其中六种是通用结构，八种是内容风格：除了故事线，还规定旁白的口吻、语速和适合的时长。

| 结构 | 展开方式 | 适合 |
| --- | --- | --- |
| 黄金留存（硬核认知） | 钩子、悬念锚点、三层价值、结构化收束、无预警收尾 | 商业、科技、认知类内容 |
| 痛点-放大-解决 | 先戳痛点，再放大代价，最后给解法 | 服务、课程、工具类 |
| 故事反转 | 从结果或冲突切入，讲一个有转折的小故事 | 个人 IP、品牌故事、案例 |
| 清单盘点 | "3 个……"式清单，最有价值的一条放最后 | 技巧、避坑、盘点 |
| 教程步骤 | 先展示结果，再分步骤教 | 实操、软件、技能教学 |
| 产品种草 | 场景痛点、产品亮相、卖点证明、行动 | 带货、新品、探店 |

| 通用内容风格 | 展开方式 | 时长与语速 | 适合 |
| --- | --- | --- | --- |
| 反常识暴击／痛点止损风 | 痛点暴击、揭秘亏钱真因、三步止损法、转发指令 | 45–75 秒，4.5 字/秒 | 泛商业认知破圈、纠正企业的错误动作 |
| 情绪嘴替／社交货币风 | 具象冲突场景、戳破行业潜规则、给个说法、金句升华促转发 | 45–60 秒，4.2 字/秒 | 替创业者、高管、技术负责人说出大实话 |
| 利他工具／实战拆解风 | 结果反差钩子、前置第三步悬念、一二三步实操拆解、置顶领模板 | 60–100 秒，4.0 字/秒 | 流程 SOP、避坑清单、实操案例 |
| 具象故事／走心留白风 | 真实细节切入、事情的走向、认知转折、留白金句引发评论 | 45–75 秒，3.5 字/秒 | 创始人感悟、客户交付复盘、价值观共鸣 |

| 科技商业与顾问风格 | 展开方式 | 时长与语速 | 适合 |
| --- | --- | --- | --- |
| 硬核技术破壁风（短平快版） | 业务痛点提问、人话比喻解说、一线踩坑经验、三步落地法 | 60–90 秒，4.3 字/秒 | 讲清一个技术概念，例如《什么是 Ontology（本体）？》 |
| 顾问级深度白板授课风 | 商业神话破题、背景与演进、全局架构、微观组件与工作流解剖、认知升华、三步搭建与讲义转化 | 3–6 分钟，4.2 字/秒 | 系统拆解 Palantir、Ontology、企业 AI 新架构 |
| 科技新闻内行解说风 | 反共识泼冷水、发生了什么、外行忽略的一个细节、生产环境印证、行动预判 | 60–120 秒，4.2 字/秒 | 大模型和 Agent 重磅发布、科技巨头动态 |
| 科技公司财报透视与商业拆解风 | 揪出一组反常指标、拆这组指标、翻译成“客户在为什么买单”、一线谈单体感共振、抄作业指南 | 90–180 秒，4.0 字/秒 | 从财报看一家公司怎么赚钱 |

英文脚本的语速按同样的比例换算成每秒词数。内容风格会把自己的写作规则加进提示词。硬核技术风先讲价值再讲机制，每个术语先说人话再报名字，并用一个类比贯穿全片。白板授课风一章一章地推演同一张图，并附带板书蓝图和章节。新闻和财报风把事实和判断分开说，每个数字都在屏幕上标明口径和来源，不谈股价、不给投资建议。这两种风格讲的是事实，请把新闻原文或财报数字粘贴到 **参考资料**：资料里没有的地方，脚本会留出标明的空位（`【待核实：…】`、`【待补：…】`），并列在制作备注里，不会编造。

**画面风格** 提供 57 种风格，分为六组。

| 分组 | 风格 |

| 图形与数据 | 动态信息图、极简几何、科技界面、屏幕演示 |
| 明亮与浅色 | 明亮通透、明亮科技、奶油浅色、北欧浅木、马卡龙色、多巴胺、日系清新、森系自然、夏日晴空、海岛度假、落日余晖、晨雾空灵、柔光氛围 |
| 年代与氛围 | 古风、黑白老电影、装饰艺术、老上海月份牌、中古摩登、复古未来、复古胶片、年代怀旧、港风、录像带、像素风、千禧 Y2K、蒸汽波、霓虹夜色、赛博朋克、蒸汽朋克、废土、暗调质感、暗黑学院、治愈暖调、侘寂、超现实梦境 |

可以选一种，或选两种混合。先选的为主；再选第三种时，会替换掉最早选的那一种。所选风格有两个作用：

1. 告诉写作模型这种风格能呈现什么，让每个场景的画面和镜头描述与之相配。
2. 写进这份脚本所有图片和视频的提示词。

写脚本时没有选风格的，生成图片和视频时会使用当时选中的风格。

## 图片和视频

**每个场景的图片数**（1 到 3，默认 1）决定每次点击 **生成图片** 或自动出图时，为一个场景生成几张图。每张图都是对图像模型的一次单独请求。

生成两张或三张时，旁边的下拉框决定这几张图之间的关系：

| 模式 | 2 张 | 3 张 | 用途 |
| --- | --- | --- | --- |
| 备选方案 | 同一镜头两张 | 同一镜头三张 | 多生成几张，挑最好的 |
| 动作节拍 | 开始、结束 | 开始、中段、结束 | 做轮播，或作为图生视频的首尾帧 |
| 多景别 | 全景、特写 | 全景、中景、特写 | 在一个场景内剪切 |
| 主镜头 + 插入镜头 | 主镜头、细节插入 | 主镜头、细节插入、环境空镜 | 用于穿插剪辑 |
| 风格对比 | 风格 A、风格 B | 风格 A、风格 B、混合 | 在所选的两种画面风格之间做选择 |

每张图都有自己的提示词：场景的画面描述，加上这张图对应的拍法。多景别和插入镜头会替换场景原有的镜头描述，动作节拍则保留。每张图下方会标注它的角色，压缩包里的文件名也会带上（如 `scene-01_00m00s-00m04s_1-wide.png`）。

> **提示：** 各张图是独立生成的。提示词会要求同一组图保持主体、场景和色调一致，但图像模型仍可能有差异。

视频片段的时长取 4、8、12 秒中能覆盖该场景的最短一档；超过 12 秒的场景按 12 秒生成。

## 连接模型

生成内容通过 **网关** 完成。一个网关包含服务商、接口地址、API 密钥和模型。

| 设置 | 模型设置中的字段 | 环境变量 |
| --- | --- | --- |
| 服务商 | 服务商 | `LLM_PROVIDER` |
| 接口地址 | BASE_URL_API | `BASE_URL_API`（或 `LLM_BASE_URL`） |
| API 密钥 | API_KEY | `API_KEY`（或 `LLM_API_KEY`） |
| 模型 | 默认模型 | `LLM_MODEL` |

### 支持的服务商

OpenAI、Anthropic (Claude)、DeepSeek、通义千问、豆包、Moonshot Kimi、智谱 GLM、Google Gemini、OpenRouter、Ollama（本地），以及自定义的 OpenAI 兼容接口、Anthropic 兼容接口和离线演示。

预设的接口地址和模型名称只是起点，请按你的账号实际情况修改。

### 保存多个网关

在 **模型设置** 里可以保存任意多个网关，每个服务商或账号一个。可以编辑、删除，并在要用的那个上勾选 **用这个网关写脚本**。

- 保存的网关写入 `data/gateway.json`，优先级高于环境变量。环境变量只在没有保存任何网关时提供初始网关。
- **测试连接** 可以在保存之前检查网关设置是否可用。

### 模型

**列出可用模型** 会向服务商查询当前密钥可以使用哪些模型。勾选想用的模型并选定默认模型后，所有已保存网关中勾选的模型都会出现在需求里的 **写作模型** 选择器中，管理员不用打开设置就能切换网关和模型，选择对所有人生效。

如果服务商没有模型列表接口，直接输入模型名称即可。

### 图像和视频模型

每个网关都有 **图片和视频** 一栏，可以为图片和视频分别设置 BASE_URL_API、模型、尺寸和可选的 API_KEY。

- 接口地址或密钥留空时，使用网关本身的设置。
- 模型留空即关闭该类生成。
- 尺寸只在填写后才会发送。
- **列出可用图像模型** 和 **列出可用视频模型** 会向对应地址查询模型。服务商会返回它的全部模型，名称看起来像图像或视频模型的会排在前面。

## 你的内容

所有内容都保存在服务端，并按用户隔离。

| | 本地运行（`npm start`） | 线上部署（设置了 `DATABASE_URL`） |
| --- | --- | --- |
| 脚本、用户、会话、用量、活动日志、网关 | `data/<名称>.json` | Postgres 表 `vs_docs` |
| 生成的图片和视频 | `data/media/` | Postgres 表 `vs_blobs` |

图片和视频是私有的，只有所有者和管理员可以打开。

从历史记录重新打开脚本时，它的图片和视频会一并显示，写这份脚本时用的简报（主题、平台、结构、时长、风格和各项细节）也会填回表单，方便修改后再次生成。每次生成都会保存为一份新脚本，有自己的素材包；原来打开的那一份保持不变。重新生成图片或视频不会删除旧文件，界面显示最新的一份。如果服务商返回的是链接而不是文件，文件也会被下载并保存。

备份或迁移到另一台电脑时，复制整个 `data/` 目录即可。

### 下载的压缩包

**下载 .zip** 为每份脚本生成一个压缩包，文件名为 `<日期>_<平台>_<标题>.zip`，例如 `2026-11-10_douyin_AI-落地的三个坑.zip`。标题保留各种语言的文字，标点和空格换成连字符，最长 40 个字符。压缩包内是一个同名文件夹：

```
script.md                              完整脚本，使用界面语言
script.html                            同样内容的网页版，带图片和视频，可离线打开
script.json                            需求、计划、脚本，以及媒体文件列表
voiceover.txt                          只有旁白，每个场景一段
images/scene-01_00m00s-00m04s.png      每个场景最新的图片
videos/scene-01_00m00s-00m04s.mp4      每个场景最新的视频片段
```

一个场景有多张图片时，文件名会加上序号，有角色的还会带上角色：`…_1.png`，或 `…_1-start.png`、`…_2-end.png`。

## 账号、用量与活动日志

- **注册和登录**：邮箱加至少 8 位的密码，会话有效期 30 天。
- **两种角色**：*成员* 可以写脚本、生成图片和视频，并查看自己的历史、用量和活动；*管理员* 还可以管理模型网关（网关和模型由管理员统一设置并对所有人生效；成员看不到接口地址和密钥，只能看到正在使用的网关和模型），以及查看和管理所有用户。
- **第一个管理员** 由环境变量 `ADMIN_EMAIL` 和 `ADMIN_PASSWORD` 创建。注册不会获得管理员权限；管理员在 **用户管理页**（`/admin.html`，顶部栏和账号面板中都有入口）管理其他所有人。
- **用量**：每一次模型调用都会记录：谁调用的、属于哪份脚本、用了哪个网关和模型、输入和输出 Token、生成的图片数、视频秒数、耗时以及是否失败。**账号 → 用量** 按时间段显示总量，并按脚本、按模型、逐次调用列出；管理员可以切换到 **所有用户** 查看每个用户的用量。服务商不返回 Token 数时按文本估算，并标记为 ≈。
- **活动日志**：**账号 → 活动日志** 记录注册、登录和登录失败、脚本生成、图片和视频生成、打包下载，以及网关和用户的变更。密码和 API 密钥不会写入日志。
- 设置 `ALLOW_SIGNUP=false` 可关闭注册。

- **个人资料**：任何人都可以在 **账号 → 个人资料** 中修改自己的显示名称和密码；修改密码后其他设备会退出登录。
- **显示密码**：所有密码和 API 密钥输入框都有一个眼睛按钮，可以显示已输入的内容。
- **用户管理页**（仅管理员）：列出所有账号及其角色、状态、最近登录、脚本数和用量，支持搜索和筛选。管理员可以创建用户（密码可手动输入或自动生成）、修改姓名、邮箱、角色和状态、重置密码、强制在所有设备退出登录、查看单个用户的会话、累计用量和最近活动，以及删除用户（可选择删除其脚本和素材，或转到管理员名下）。管理员不能降级、停用或删除自己的账号。

暂未包含：邮箱验证和通过邮件自助找回密码；忘记密码时由管理员重置。

## 部署到 Vercel

仓库可以直接部署：`vercel.json` 选择 "Other" 框架预设，把 `public/` 作为静态文件，并把 `/api/*` 和 `/media/*` 交给一个 Node.js 函数（`api/index.mjs`）。

1. **添加 Postgres 数据库**：在 Vercel 项目的 **Storage** 中创建 Postgres（Neon）数据库，它会自动加入 `DATABASE_URL`。数据表在第一次请求时自动创建。
2. **添加两个环境变量**：`ADMIN_EMAIL` 和 `ADMIN_PASSWORD`（密码请标记为 Sensitive）。
3. **重新部署**，打开网站，用管理员账号登录，在 **模型设置** 中连接模型。

没有 `DATABASE_URL` 时网站仍可运行，但使用的是临时存储，函数重启后账号、脚本和设置都会丢失；此时管理员在账号面板中会看到提示。

## 隐私与安全

- **需要登录。** 除注册和登录外，所有接口都需要会话，并拒绝跨站请求。
- **不保存密码原文。** 只保存加盐的 scrypt 哈希；连续 5 次输错密码会锁定账号 15 分钟。
- **密钥留在服务端。** 每个密钥随所属网关保存，管理员只能看到打码后的预览，成员完全看不到。
- **密钥不会发给别的服务。** 更改网关的服务商或接口地址会清除已保存的密钥。
- **不进入版本库。** `data/` 已加入 .gitignore。

你的需求和参考资料只会发送给你选择的模型服务商。

## 访客与转化

管理页的 **用户 → 访客** 标签显示首页访客如何变成用户：

- **转化漏斗。** 访客数，以及其中点击了进入应用的按钮、打开了应用、完成注册、写了第一份脚本的人数，各占访客的比例。
- **分组统计**：按来源（来源网站，或链接上的 `utm_source`）、首次看到的页面、日期、国家或地区、设备，每组都有注册数和转化率。
- **最近的访客**：每位访客走到了哪一步，注册后对应哪个用户。

访客按首次访问的时间归入统计周期，来源只记第一次的。原本就有账号的人单独统计，所以转化率只针对潜在用户。爬虫和脚本不计入。

实现方式：首页和应用加载 `public/track.js`，把页面浏览和进入应用的按钮点击发送到 `/api/track`。服务器给每个浏览器一个随机编号，保存在第一方 Cookie（`vs_vid`，一年）里，每位访客一条记录。不保存 IP 地址，也不向任何第三方发送数据。由于这个 Cookie 并非严格必需，在某些地区（例如欧盟和英国）可能需要先告知访客或征得同意，如适用请自行添加提示。

分享链接时，在首页地址后加上 `?utm_source=newsletter`（还可以加 `utm_medium`、`utm_campaign`）即可区分来源。

## 首页与搜索

`/` 是公开的首页（`public/index.html`，简体中文版是 `public/zh.html`）；应用本身在 `/app.html`，并标记为 `noindex`。首页是纯静态 HTML，包含搜索引擎和 AI 问答引擎会读取的内容：

- 标题、描述、canonical 链接，以及两种语言之间的 `hreflang` 链接
- Open Graph 和 Twitter 标签，以及分享图片（`public/og.png`）
- 结构化数据（`SoftwareApplication`、`HowTo`、`FAQPage`），与页面上的文字逐字一致，`npm test` 会检查
- `robots.txt`、`sitemap.xml`，以及给语言模型看的纯文本摘要 `llms.txt`

这些都需要站点的公开地址。设置 `SITE_URL`（例如 `https://example.com`）即可。在 Vercel 上默认使用项目的正式域名，构建时写入文件；用 `npm start` 运行时默认使用每个请求的访问地址。

## 界面

- **语言。** 顶栏的 **中文 / English** 按钮在简体中文和英文之间切换界面。在你选择之前，界面跟随浏览器语言。服务端和模型服务商返回的信息仍为英文。
- **主题。** 顶栏的太阳 / 月亮按钮在浅色和深色之间切换。在你选择之前，页面跟随系统设置。
- **四步填写需求。** 你的视频、脚本结构、画面与图片、补充信息。后两步默认折叠，只显示一行摘要。**生成** 栏始终在手边。
- **桌面端。** 左边是需求，右边是脚本。历史记录和模型设置从顶栏打开。
- **手机端。** 一次只显示一个视图，底部导航栏有创作需求、脚本、历史记录、设置四项。开始生成后会自动切到脚本视图，设置和历史记录以全屏面板打开。控件高度不低于 44px，输入框使用 16px 文字，在 iOS 上点击输入框时页面不会被放大。
- **历史记录。** 带缩略图的列表，可以搜索。
- **写作过程中。** 进度视图会显示模型正在写第几个场景；原始回复可通过"查看原始回复"展开。

颜色、间距和字体都定义为 `public/styles.css` 顶部的设计变量（中性锌灰配一种粉色强调色，含浅色和深色两套）。图标是 `public/icons.js` 里的内联 SVG。字体优先使用本机已安装的 Inter，否则使用系统字体。页面不下载任何网络字体，因此离线或无法访问 Google Fonts 时也能正常使用。

### 按需定制

| 想改什么 | 修改位置 |
| --- | --- |
| 某个平台的脚本写法 | `src/platforms.mjs` 中该平台的条目，文字会直接进入系统提示词 |

| 旁白智能体懂什么、按什么标准审稿 | `skills/` 里的技能：改一份，或加一个文件夹 |
| 旁白质检量什么，以及平台会限流的词 | `src/agent/review.mjs`，和 `src/platforms.mjs` 里的 `banned` |
| 旁白编辑器提供的润色方式 | `src/prompt.mjs` 里的 `REFINE_PRESETS` |
| 画面风格 | `src/styles.mjs` |

| 服务商预设 | `src/gateway/providers.mjs` |
| 界面翻译 | `public/i18n.js` |

"黄金留存"结构来自 B2B 4K 短视频技能（钩子、悬念锚点、三层价值、结构化收束、无预警收尾）；中文脚本里"英文只出现在屏幕上、不进旁白"的规则也出自同一来源。三种科技与商业解说风格参考了旁白、故事主线和解说片几个技能：钩子用观众自己的话说，价值先于论据，细节放在屏幕上、旁白只讲主干，每个说法要么有出处，要么标明是创作者的判断。四种通用内容风格、白板授课风、3 + 3 + 4 三维观点卡、视频号的增长与合规规则，以及企业 AI 知识底座，来自《微信视频号高完播与顾问级获客脚本系统规范》，并拆成了上面这些技能。

### 接口协议

`src/gateway/client.mjs` 实现了两种协议，均为流式：OpenAI 兼容的 `chat/completions` 和 Anthropic 的 `messages`。

| 用途 | 请求 |
| --- | --- |
| 列出模型 | `GET {base}/models`，Anthropic 为 `/v1/models` |
| 生成图片 | `POST {base}/images/generations` |
| 发起视频任务 | `POST {base}/videos` |
| 查询视频任务 | `GET {base}/videos/{id}` |
| 下载视频 | `GET {base}/videos/{id}/content` |

图片和视频生成使用 OpenAI 兼容的媒体接口。

### HTTP API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/meta` | 平台、脚本结构及分组、润色方式、语速和服务商预设 |
| `GET` | `/api/gateway/config` | 所有已保存的网关（密钥已打码）和当前使用的网关 |
| `PUT` | `/api/gateway/config` | 新建网关，或更新指定 `id` 的网关；`activate: true` 表示启用它 |
| `POST` | `/api/gateway/select` | `{ id, model? }` 选择用来写脚本的网关及其已启用的某个模型 |
| `POST` | `/api/gateway/delete` | `{ id }` 删除网关 |
| `POST` | `/api/gateway/test` | 测试请求体中的设置，不保存 |
| `POST` | `/api/gateway/models` | 按请求体中的设置列出服务商的模型，不保存；`kind: "image" \| "video"` 改为向对应的地址查询 |
| `GET` | `/api/history` | 所有已保存的脚本，最新的在前 |
| `POST` | `/api/history` | 保存一份脚本 |
| `POST` | `/api/history/package` | `{ id, markdown }` 返回该脚本的 `.zip` |
| `POST` | `/api/media/image` | `{ visual, camera, historyId, sceneId }` 生成并保存一张图片，返回 `{ url }` |
| `POST` | `/api/media/video` | `{ visual, camera, start, end }` 发起一个视频任务 |
| `POST` | `/api/media/video/status` | `{ id, historyId, sceneId }` 查询任务，完成后保存文件 |
| `GET` | `/media/<file>` | 已保存的图片或视频 |
| `POST` | `/api/plan` | 只返回一份需求的计划，不写任何内容：带时间的故事线、时长和旁白预算 |
| `POST` | `/api/narration/draft` | 只写旁白，每个阶段一段：智能体的“策划并写作”步骤；带 `agent: false` 时只做一次普通起草。服务器发送事件（SSE）：`plan`、`step`、`delta`、`done`（`{ narration, card, report }`）或 `error`。不保存任何内容 |
| `POST` | `/api/narration/review` | `{ ...需求, narration, card? }` 智能体的审稿步骤。服务器发送事件（SSE）：`plan`、`step`、`delta`、`done`（`{ beats, report }`）或 `error` |
| `POST` | `/api/narration/check` | `{ ...需求, narration, card? }` 只做量化检查，返回 `{ findings, errors, warns, stats }`，不调用模型 |
| `POST` | `/api/narration/refine` | `{ ...需求, narration, index?, preset?, instruction?, target? }` 改写某一段（返回 `{ text }`）或全文（返回 `{ beats }`）；`preset: "review"` 执行智能体审稿，返回 `{ beats, report }` |
| `POST` | `/api/generate` | 带 `narration: [{ stage, text }]` 时，脚本围绕这些话原样生成，随它一起发来的 `card` 会保存在脚本上。服务器发送事件（SSE）：`plan`、`delta`、`done` 或 `error` |
